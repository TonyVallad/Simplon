Data Pipeline

Efficient pipelines keep GPUs busy and ensure reproducibility.

  • Shuffling per epoch; stratify if imbalanced.
  • Augmentation for images/audio; time-preserving transforms for sequences.
  • Num workers to saturate I/O; prefetch and pin memory.
  • Determinism: fix seeds; log versions and hashes; freeze data splits.

Initialization

Goal: start training so that signals and gradients neither explode nor vanish as they pass through layers. Good initialization keeps the variance of activations and gradients roughly stable across depth.

Intuition: If weights are too large, activations/gradients explode. If too small, they shrink to zero. We pick the initial weight scale using the layer size (fan-in/fan-out) and the activation type.

Why it matters

  • Faster convergence: fewer steps to reach a good solution.
  • Stability: avoids NaNs and degenerate flat regions.
  • Better signal flow: gradients reach early layers in deep nets.

Which initialization to use?

ActivationRecommended initRationale
ReLU / LeakyReLU / GELU / SiLUKaiming/He (fan-in)Accounts for half activations being zero (ReLU-family).
tanh / sigmoidXavier/Glorot (fan-avg)Balances variance across layers for saturating activations.
Linear outputs (regression)Small std (e.g., 1e-3)Start predictions near zero without saturating loss.
Classification logitsSmall std or zeroPrevents overconfident early predictions.

PyTorch examples

# Apply Kaiming (He) init for ReLU-like activations; Xavier for tanh/sigmoid
import torch
import torch.nn as nn
import torch.nn.functional as F

def init_module_parameters(module: nn.Module) -> None:
  for m in module.modules():
    if isinstance(m, (nn.Conv2d, nn.Linear)):
      # Choose based on the activation used after this layer
      nn.init.kaiming_normal_(m.weight, nonlinearity='relu')  # ReLU/LeakyReLU/GELU/SiLU
      if m.bias is not None:
        nn.init.zeros_(m.bias)
    elif isinstance(m, (nn.GRU, nn.LSTM)):
      for name, param in m.named_parameters():
        if 'weight_ih' in name or 'weight_hh' in name:
          nn.init.xavier_uniform_(param)  # good default for recurrent weights
        elif 'bias' in name:
          nn.init.zeros_(param)

# If you use tanh/sigmoid immediately after a layer, prefer Xavier:
def xavier_for_tanh(layer: nn.Linear) -> None:
  nn.init.xavier_uniform_(layer.weight, gain=nn.init.calculate_gain('tanh'))
  if layer.bias is not None:
    nn.init.zeros_(layer.bias)

# Final layer heads
def init_classification_head(head: nn.Linear) -> None:
  nn.init.zeros_(head.weight)
  nn.init.zeros_(head.bias)

def init_regression_head(head: nn.Linear, std: float = 1e-3) -> None:
  nn.init.normal_(head.weight, mean=0.0, std=std)
  nn.init.zeros_(head.bias)

Practical tips

  • Biases: initialize to zero in most cases. For LSTMs, setting forget gate bias positive (e.g., 1.0) can help retain information early.
  • Normalization layers: keep defaults (e.g., BatchNorm weight=1, bias=0). Do not apply He/Xavier to norm params.
  • Residual nets: consider smaller init for residual branches or use zero-init last BN in residual blocks to start near identity.
  • Transformers: use framework defaults (often Xavier) with careful LayerNorm placement; small init for output heads.
Sanity checks: before training, run a forward pass on a batch and verify that (a) activations are finite, (b) gradient norms are not zero or enormous, and (c) initial loss is finite. If gradients explode, reduce LR or check init. If they vanish, switch to He/Xavier as appropriate.

Forward & Backward

  1. Forward pass computes predictions.
  2. Loss compares predictions to targets.
  3. Backward pass computes gradients (autodiff).
  4. Optimizer updates parameters.
# PyTorch sketch
scaler = torch.cuda.amp.GradScaler(enabled=use_amp)
for epoch in range(epochs):
  model.train()
  for x, y in train_loader:
    optimizer.zero_grad(set_to_none=True)
    with torch.cuda.amp.autocast(enabled=use_amp):
      y_hat = model(x)
      loss = criterion(y_hat, y)
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()

  model.eval(); val_loss = 0.0
  with torch.no_grad():
    for x, y in val_loader:
      y_hat = model(x)
      val_loss += criterion(y_hat, y).item()
  scheduler.step(val_loss / len(val_loader))

Schedulers

  • Step decay: drop LR at milestones.
  • Cosine with warmup: smooth decay; strong default.
  • One-cycle: cyclic schedule that can speed convergence.

Mixed Precision (AMP)

Use float16/bfloat16 where safe to accelerate training and reduce memory, keeping master weights in float32.

Checkpoints

Save model weights, optimizer state, epoch, and RNG states. Keep best-by-metric and last. Store configs alongside for reproducibility.
