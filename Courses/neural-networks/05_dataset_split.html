5. Dataset Split

Honest evaluation requires clean separation. Avoid leakage, stratify, and match your domain constraints.

On this page

  • Why Split?

  • Leakage
  • Versioning

Why Split?

We estimate generalization to unseen data and tune hyperparameters without bias.

  • Train: fit parameters.
  • Validation: model selection and early stopping.
  • Test: final unbiased report; use once per dataset.

Split Strategies

  • Random + stratified to preserve class ratios.
  • Group-aware when multiple samples share identity (patient, user, scene).
  • Time-series: forward-chaining or train-before-test in time.
  • Cross-validation: k-fold, stratified k-fold, group k-fold for small datasets.
# scikit-learn examples
from sklearn.model_selection import train_test_split, StratifiedKFold, GroupKFold

# Stratified holdout
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

# Group-aware (e.g., patient_id groups)
gkf = GroupKFold(n_splits=5)
for tr_idx, te_idx in gkf.split(X, y, groups=patient_id):
    X_tr, X_te = X[tr_idx], X[te_idx]
    y_tr, y_te = y[tr_idx], y[te_idx]

# Time-series split (sklearn's TimeSeriesSplit or custom by timestamp)

Leakage

Information from validation/test sneaks into training, inflating performance.

  • Normalize using train-only statistics; fit encoders on train split only.
  • Deduplicate across splits; avoid near-duplicates.
  • Ensure identities (patients/users/scenes) do not span splits.
  • Perform feature selection and hyperparameter tuning strictly inside training folds.
Example: Standardize with fit on train, then transform train/val/test using the same scaler.

Versioning

Record split indices, seed, and data snapshot. Store alongside model artifacts for reproducibility.
